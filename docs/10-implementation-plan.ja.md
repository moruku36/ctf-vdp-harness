# 10 既存AI向け実装計画

[English](10-implementation-plan.md) | [ホーム](../README.ja.md)

実装主体はMorukuが選んだ既存のChatGPT／Codexです。分野を増やす前に、小さな処理を一本通します。本書自体をデプロイや環境変更の許可として扱いません。

## 作業単位

| 作業 | 成果物 | 受入・依存 |
|---|---|---|
| P0 棚卸しと現状測定 | 実ホスト／ゲスト資源、VMスナップショット、クライアント／接続能力、ツール一覧、ライセンス・版、現状Aを記録。 | 観測済みと計画を分離。J1の優先順、J2のvNIC追加、J3の拡張方向は決定済み。J4 Burp／J5 REAは保留でよく、初期構成の依存にしない。 |
| P1 契約とオフライン搬入 | 調査マニフェスト、スコープ検証、資料ID・ハッシュ、共通結果、非公開証拠ページ、監査要約。 | スコープ欠損・期限切れ、不正ID、領域外パス、過大入力を拒否。レポート雛形に対応。通信・大会提出・動的デバッグは無効。 |
| P2 解析器を一つ受入 | まず軽く有用な既存Workbench／ヘルパー機能。上流コミットを固定し、受入した型付き操作のみ有効。 | 管理下入力から再現可能な観測と証拠参照を生成。長い原文も取得可能。tools/listだけでなく実行を検証。 |
| P3 状態と復旧 | 仮説台帳、操作履歴、予算、取消、プロセス終了、再起動挙動、証拠書き出し。 | 合成試料で搬入→観測→仮説更新→独立検証→レポート→復元が通る。証拠欠損・合成機微マーカー流出なし。 |
| P4 対話アダプタ | 必要性を確認したデバッガ／接続アダプタを一つ。 | 型付き操作、資料／対象の紐付け、期限、切断、残存プロセス。動的実行プロファイルは分離。 |
| P5 オフライン比較 | 09に基づくA／B／C。Dは開発用の手順改訂後。 | 全課題・失敗・悪化を記録。横ばいも有効な結果として扱い、証拠なしに改善を主張しない。 |
| P6 実クライアント接続 | Secure MCP Tunnel優先。不可なら既存の認証付きHTTPS代替。隔離vNICとラボ受入記録を先に整合。 | 各クライアントで認証、一覧制御、証拠ページ、再接続、拒否を確認。ゲストから自宅LAN・管理面へ到達せず、閲覧用サービスを公開しない。 |
| P7 対象限定CTF／VDP | プログラム別スコープ、制限付きリクエスト、ローカル脆弱版／修正版試料。 | ローカルで予算、DNS・転送、対象外、期限を確認。実対象の許可は実際の規約に基づく。Burpは任意で前提にしない。 |
| P8 任意の拡張 | CTFd、追加分野、資源拡張、必要なら複数エージェント比較。 | 個別の受入記録と実験。初期実装では外部自動提出なし。 |

P1〜P5はJ4／J5を待たずローカル経路で進められます。P6／P7は基盤・対象許可に依存し、オフライン試行の成功だけで完了扱いしません。記録上のvNICなしゲストには通常のSSHで直接入れないため、まず既存コンソールとオフライン搬入を使うか、承認済み隔離ブリッジを受入してから接続します。

## 実装時の構成案

以下は予定です。今回追加するのは文書、雛形、非実行の設定例だけです。

```text
src/ctf_mcp/
  gateway/       # 利用者・スコープ・ツール一覧・予算・監査
  runs/          # 調査記録・仮説・操作状態・期限
  adapters/      # 受入済みOSSへの限定ラッパー
  evidence/      # 取込検証・出所・ページ・書き出し
  verification/  # 登録したローカル結果検証
  server.py      # MCP登録。汎用execは置かない
tests/
  contracts/     # 型付き要求／結果と認可
  integration/   # 所有試料・取消・復旧
  evaluation/    # 固定課題一覧と比較実行
```

従来案のPython 3.12+／uv／FastMCPを引き継ぎ、固定版で互換性を確認します。契約を満たす既存実装は再利用。小さな不足のために新しいエージェント基盤、全ツール入り環境、汎用シェルラッパーを作りません。作業ガイドは小さくし、上流の長いプロンプトやコードをライセンス確認なしで複製しません。

## 実装担当から残すもの

作業ごとに、レビュー可能な変更として以下を残します。

- 変更内容、固定依存版・ライセンス根拠、有効化した機能。
- 入力、試料結果、エラー・取消の挙動、資源実測、残る限界。
- 再現手順、移行・巻戻しの影響。
- 実際に必要な未決事項だけ。J1〜J3の決定を包括確認として聞き直さない。

設計上の機能名を上流に対応付ける前に、実ツール定義を確認します。秘密情報はGit外に置き、例に実接続先・認証情報を含めません。[設定例](../configs/offline-pilot.example.json)は意図的に全無効で、起動用の正式設定ではありません。

## 最初の実用版の完了条件

既存AIが**受入済みオフライン解析を一つ**呼べて、原文証拠をページ取得し、復元可能な仮説を更新し、独立したローカル検証と再現可能なレポートを得られること。時間超過・切断で追跡不能な処理が残らないこと。性能改善を測定済みかどうかも明示します。

追加ツール、実対象通信、Burp、REA、大会提出は、この最初の完了を妨げず後から追加できます。
